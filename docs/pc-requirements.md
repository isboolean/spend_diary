# PC 端记账功能需求文档

> 版本：v1.0 ｜ 日期：2026-11-03 ｜ 范围：admin-web（PC Web 记账本）

## 1. 背景与目标

App 端（Expo RN）界面设计已确定（6 张截图：首页概览、记一笔、账单明细、统计图表、预算/分类/账户、我的/设置）。
本期目标是让 PC Web 端功能与 App 对齐，补齐 PC 端目前缺失的四块能力：

1. 首页仪表盘（现在登录后直接落在账单页，无聚合首页）
2. 账户管理（现在只有注册时自动创建的「现金」账户，无管理入口）
3. 账单搜索筛选（现在仅支持月份 + 支出/收入类型）
4. 统计图表可视化（现在统计页只有数字卡片 + 表格）

## 3. 功能需求

### FR-1 首页仪表盘

**描述**：用户登录后默认落地首页 `/home`，聚合展示本月财务概览与最近账单。

**页面内容**：
- 今日支出、今日收入（取自月度统计每日数据，无数据显示 0.00）
- 本月支出 / 本月收入 / 结余
- 月度预算进度：已用金额、剩余金额、进度条（超预算红色警示）
- 最近账单：最近 10 条（日期、分类图标+名称、金额正负着色、备注）
- 「记一笔」快捷按钮：跳转账单页并自动打开记一笔弹窗

**数据来源**：复用现有接口 `getMonthlyStats(month)`、`getBudget(month)`、`listTransactions(month)` 客户端聚合，**不新增后端接口**。

**验收标准**：
- 登录后首页各项数据与账单页 / 统计页 / 预算页一致
- 无账单的月份：支出收入均显示 0.00，最近账单显示空态
- 点击「记一笔」落到账单页且弹窗已打开

### FR-2 账户管理

**描述**：新增页面 `/accounts`，支持多账户（现金、银行卡、支付宝、微信、其他）的增删改。

**列表字段**：名称、类型标签、余额（两位小数）、操作（编辑 / 删除）。

**新增账户**：
- 名称：必填，1–16 字
- 类型：必选（CASH / BANK_CARD / ALIPAY / WECHAT / OTHER，枚举新增 OTHER）
- 初始余额：可选，两位小数，允许负数（信用卡场景），默认 0

**编辑账户**：仅名称 / 类型可改；余额由账单自动联动维护，不提供手动改余额（纠错通过记一笔收入/支出实现）。

**删除账户**：
- 该账户下存在账单 → 拒绝，提示「该账户下已有账单，不能删除」（新错误码 1005 ACCOUNT_IN_USE）
- 该账户是唯一账户 → 拒绝，提示「至少保留一个账户」（新错误码 1006 ACCOUNT_LAST_ONE）

**后端接口**（均在 `/api/v1/app` 下，沿用 ApiResponse 约定）：
- `POST /accounts` 入参 `{name, type, initialBalance}` → AccountVO
- `PUT /accounts/{id}` 入参 `{name, type}` → AccountVO
- `DELETE /accounts/{id}` → 成功或 1005 / 1006

**数据模型**：`accounts` 表字段已满足（name/type/balance），无需改表；AccountType 枚举加 `OTHER`。

**验收标准**：
- 新增账户后出现在列表与账单记一笔的账户下拉中
- 删除被引用的账户返回 1005 并前端提示
- 删除唯一账户返回 1006 并前端提示
- 账户余额随记账自动联动（已有能力，回归验证）

### FR-3 账单搜索筛选

**描述**：账单页工具区在现有「月份选择器 + 支出/收入类型」基础上，新增关键词、分类、账户筛选，可组合生效。

**筛选条件**：
- 关键词：备注模糊匹配（`note LIKE %kw%`）
- 分类下拉：全部 + 全部分类（支出/收入都列出）
- 账户下拉：全部 + 全部账户

**后端扩展**：`GET /transactions` 增加可选参数 `keyword`、`categoryId`、`accountId`，与 `month`、`type` 组合查询。

**验收标准**：
- 单条件与组合条件结果正确
- 清空条件恢复当月全量列表
- 无匹配结果显示空态

### FR-4 统计图表可视化

**描述**：统计页在现有卡片与表格基础上新增两块 echarts 图表。

**图表**：
1. 每日收支趋势：当月每日支出 / 收入双系列柱状图（支出红、收入绿）
2. 分类支出占比：环形图（支出分类金额占比，占比 < 2% 的小分类合并为「其他」）

**技术**：引入 `echarts`，仅统计页按需引入；不引入额外 wrapper。

**验收标准**：
- 有账单月份图表正确渲染，数值与表格一致
- 无账单月份图表显示空态提示
- 切月后图表同步更新

## 4. 非功能需求

- 鉴权：全部走现有 JWT + RequireAuth，无新增鉴权模型
- 约定：沿用 `ApiResponse{code,message,data}`，业务错误 HTTP 200 + code
- 金额：后端 BigDecimal 两位小数；前端展示统一 `toFixed(2)`
- 前端技术栈不变：React 18 + antd 5 + axios；仅新增 echarts 一个依赖

## 5. 非本期范围（明确不做）

- 多账本（当前单人单账本）
- 周期账单 / 模板、数据导出、消息提醒
- 后台管理 + 角色控制（已排期为独立任务 #19）
- 「我的 / 设置」独立页面（昵称展示 + 退出登录已由顶栏覆盖）

## 6. 验收清单汇总

1. 登录落地首页，四项汇总 + 预算进度 + 最近账单正确
2. 账户增删改全流程可用，删除限制（1005/1006）生效
3. 账单页关键词 / 分类 / 账户筛选组合正确
4. 统计页两张图表渲染正确且随月份联动
5. 回归：记一笔、编辑、删除、预算、分类管理无异常
6. `npm run build` 通过（tsc + vite）
